# 发布清单 v1.0.50（C19：项目逾期口径细化 + 交付同步修复）

## 背景与根因（真实数据实证）
- 用户截图：项目汇总 9 张卡片全部红标「逾期 4 天」，与 KPI「已逾期 9」对得上但业务上不对。
- `~/.supplydev/backups` 最新备份：9 个逾期项目 targetDate 全为 2026-09-22（种子日 T-3）。
- 审计日志：车载手机支架（09-25 22:42）、电动洁面仪（09-26 11:16）「交付」里程碑已完成、进度已联动 100%，**项目汇总仍红标逾期** → 数据不同步。
- 打样中/立项中项目（打样截止 10 月）被过去的目标交期误标逾期 → 「有些是错误的」。

## 改动
- 新增 `projDueDate(p)`：立项中/打样中 → sampleDue 优先；其余 → targetDate 优先；缺失回退。
- 新增 `projDelivered(p)`：交付基线里程碑已完成 → 已交付。
- 新增 `projDueState(p)`：terminal / delivered / overdueState 三分支（逾期算术红线不变）。
- `projHealth` 改为委托 projDueState（delivered → rank2 绿「✓ 已交付」）。
- 消费点切换：项目汇总 KPI（已逾期/即将到期/本月到期）、projStatusMatch（__over/__soon7/__due30）、renderProjectRows 倒计时列+悬浮说明、仪表盘本月到期、甘特图（overdue 守卫 + st2 标签 + tip）。
- `editMilestone`：完成「交付」里程碑后 toast 提示同步结果（结转仍为人工口径，不自动改状态）。
- verify.js：更新 C15×2 / C16×1 / C17×2 旧源码锚点；新增 C19 批次 17 条（9 源码 + 8 行为级，含交付同步核心断言与 KPI 渲染断言）。
