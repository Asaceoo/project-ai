## 三、对抗性审查结论（三视角 + 工具闭环真实报错）

- **实现者**：presetT 仅接受代码内字面量（'task'/'ms'/'group'），无注入面；旧调用全部单参兼容。
- **审查者**：保存回调零改动 → C11/C13/C15 红线不受影响；C27「类型三选双站点」断言仍==2（全绿佐证）。
- **AI 使用方（工具闭环抓到并修正 4 处）**：
  1. 2a 保存静默中止 → 探针实证 `#f-msgroup` 缓存值 c30g 残留（verify elCache 跨批次不清理，C30 批次设过）→ 批次内显式清空全字段防御；
  2. **真产品缺陷：关联项目下拉默认第一项** → 端到端实证任务存进种子项目 → 修复 selected=pid + 源码断言兜底；
  3. drag=4 / 进度 50% 非预期 → 实证 targetDate 触发基线里程碑自动同步（产品固有语义）→ 断言按产品语义修；
  4. ms 计数 2/3/2 错 → ganttDrill 第三处接入 preset 后应为 task 2 / ms 3 / group 2。
- **测试基建教训（沉淀）**：①verify 沙盘 select 不反映 selected 属性到 .value，行为断言必须显式 setV；②headless Chromium **必须全新 profile**（复用旧 profile 会经 IndexedDB 预载历史数据覆盖注入种子——C30 已有教训，本次踩了变体：真缺陷被旧 profile 数据掩盖延误定位）；③修改 supplydev.html 后必须**重新生成** _shot 副本（用旧副本验证修复=假阴性）。
